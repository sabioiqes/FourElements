四大元素ゲーム 音方式 段階1テスト — フレーム送信

実験計画 v0.1 の段階1。段階0で「音が届く」ことは確かめたので、ここでは仕様 v0.1 の実寸に近い短いフレームを送って、「初回で届く割合」と「1回あたりの時間」を測る。同じファイルを2台の端末で開き、片方を送信側、片方を受信側にする。

段階0の結果（2026-11-10、Pixel＋Chromebook、0.5m・手に持つ・音量100%）: 17,500〜19,200Hz は SNR 87〜90dB で全帯域「届く」。20,000Hz も届くがノイズ床の挙動が他と違う（SNR 39.9dB）。16,500Hz は数値上は届くがユウトの耳に「脳に刺さる」感じがあり、快適さの時点で候補から外す。2,000Hz は純粋にうるさい。だから段階1の本命は 18,500〜19,200Hz。ここでは 17,500 / 18,500 / 19,200 / 20,000Hz を選べる。

使い方

  1. 両方の端末で、下の条件（帯域・距離・置き方・音量）と端末名を同じ値に合わせる。送る向き（どちらが送信側か）もここに記録する。段階0では向きが未記録だったので、今回は必ず書くこと。
  2. 受信側で「マイク開始」を押し、許可する。続けて「周囲の静けさを測る」でノイズの基準を取る。
  3. 受信側で「自動受信開始（20試行）」を押す（音を待つ状態になる）。
  4. 送信側で「自動送信開始（20試行）」を押す。1試行は約1.5秒のフレームで、20試行で約1分。
  5. 受信側の結果表に、試行ごとの成功・失敗と所要時間が出る。判定の目安は、初回成功率 95%以上（20回中19回以上）かつ、1戦分（4フレームの往復）の推定が中央値で 8秒以内。
  6. 1試行だけ確かめたいときは、手動テスト（送信で手を選んで1回送る→受信で「1フレーム待つ」）を使う。

マイクを使うには https か localhost が必要。file:// で直接開くとマイクが使えないブラウザがある。このファイルは GitHub Pages（FourElements リポジトリ）に置く想定。同じ端末1台で送信と受信を両方やる自己テストは、スピーカーとマイクが近すぎて正確な測定にならない。必ず2台で測ること。フレームの中身は測定用の符号で、暗号化はしていない（段階3の通し実験で入れる）。

送信側

送る手（手動テスト用）：

フレームの形: 開始音（中心周波数・0.4秒）→ 間隔 0.06秒 → 12ビットを2音FSKで送る（1ビット 0.08秒）。12ビットの中身は、試行番号 5ビット＋手 2ビット＋検査値 5ビット（全ビットを検査値が覆うので、1ビットの誤りは必ず検出できる）。2音は中心±400Hz（例: 18,500Hz なら 18,100Hz が 0、18,900Hz が 1）。終わりに中心周波数 0.12秒の終了音。
